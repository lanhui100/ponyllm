# WEB-09 日志：鉴权分级与网关凭证治理

## 目标
消除单 token 同权风险，并让"strict 误切导致全端 401"这类事故变成可见可防的能力。

## 时间线
1. 组队调研 provider 额度接口（11 家 → 统一 Quota API 设计），落地只读
   `GET /api/admin/quota` 与 `ponyllm-quota` skill。
2. 识别"登录鉴权与网关 token 共用一把钥匙"的安全隐患，评估后拍板 C 档
   （API Key 分级 + RBAC 矩阵）。
3. 实施 P0（`auth_compat` 三态 + 加固）、P1（作用域 key + 5 资源类矩阵 + 管理 API + CLI）、
   P2（Web 收敛与强制 logout）。
4. 红队审核 + 真机端到端验证：发现并修复"加载态渲染 0 行表格"。
5. 控制台新增「网关凭证」Tab；用户实测发现新建服务商 `billing_mode` 非法，定位并修复。
6. 治理收口：23 份调研/设计笔记从平铺改为双轴路径，`verify-note.sh` 全树通过。

## 事故记录（诚实条款）
- 验证 strict 三态时把现网切到 `strict`，而该部署仅有 legacy token，导致全端 401
  数分钟；已回切 `dual` 恢复，无数据损坏、无 secret 外泄。结论：收敛前必须先做
  staging 演练，并加"strict 且无 admin key 拒绝启动"护栏（P3）。
- 期间清理测试 key 可能使已用测试 key 的控制台会话失效，已为控制台签发
  `console-admin`(admin) 专用凭证。
