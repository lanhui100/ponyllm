## 迁移口径（迁移时的裁决，不是原文的事实）

1. **状态按事项内容判，不按旧分区判**：旧「待办」区里的 B002 自带「已完成 2026-10-02」标记 → 落 `done`；
   旧「完成」区整体按各自标记落 `done`。旧看板无「进行中」事项（原文 `## 进行中` 为「（无）」）。
2. **同号同义合并**：B002 在旧看板出现两处（`:14` 与 `:33`，同一事项的详版与简版），账本只落**一条**，
   `description` 取详版（`:14-21`），简版不复刻。
3. **无编号事项补号**：旧「完成」区的「统一账户额度计量内核」原文没有编号，迁移时补为 `B023`
   （= 已用最大号 `B022` + 1）。理由：历史事实必须有载体；补号走「接续最大号」而不是回填历史空白号段
   `B004`–`B009`——回填会让号段出现无法解释的跳变（`B023` 同样是首次使用的号，但它位于高水位序列末端，
   语义是「新号」而非「补历史」）。
4. **无同号不同义**：与部分仓不同，本仓旧看板的 `B001`–`B022` 没有「同一编号指两个事项」的冲突，
   因此**不拆号**；保留旧身份使 `docs/`、`.agents/notes/` 里既有引用继续成立。
5. **时间口径**：旧看板没有创建时间字段。`todo` 项 `created_at` 落迁移时刻（`2026-11-12`）；
   `done` 项 `created_at` 取旧看板记载的完成日期（保证 `created_at ≤ closed_at`），不臆造更早的创建时间。
6. **证据口径（诚实条款）**：`done` 记录的 `evidence` 是**指针证据**——指回旧看板原文登记的验收命令，
   迁移会话**未复跑**历史验收。即：账本证明「旧看板声称完成、登记了这些验收载体」，不证明当时确已达成。
7. **优先级口径**：旧看板未标优先级的已完成项统一落 `P1`（仅用于排序，不改变历史事实）。
8. **category 口径**：旧看板没有类别字段，迁移时按事项性质判——可复现的功能/缺陷修复落 `Defect`
   （B002/B012/B013/B018/B019/B020/B021），安全加固/技术债/范围收窄落 `Debt`（B010/B011/B014/B015/B016/B017），
   功能交付与流程任务落 `Task`（B001/B003/B022/B023）。这是迁移裁决，不是原文事实。
9. **第二份账本按「重编号补录」迁移**：`web-user-jwt-progress.md` 的 `B001`–`B004` 与旧看板编号
   **同名不同义**（波次标签），故不沿用原号，而是补录为 `B059`–`B062`（`done`，见映射表二）；
   原文仍冻结在 `backlog/legacy/`，不再作为状态真源。
10. **旧标签不得复活**：`backlog/` 之外的文档若出现「B001–B004」且无 `backlog:` 前缀与上下文，
   按历史遗留波次标签理解；新编号不得回退到这些号段（编号由 `.next-id` 单调分配）。
11. **非 `B` 编号的旧载体**：`.agents/tasks/` 下的独立任务卡（如 `P1-OPS-001`）不再作为状态真源；
