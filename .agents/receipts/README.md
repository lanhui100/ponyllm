# receipts/ —— 独立验收收据的家

> 为什么在这里：独立验收（外部拨测、实网 E2E、上线观测）的产物过去只活在会话里或仓外，
> `grep` 不到 —— 复核者拿到一句「已验收」，查不到命令、时间、退出码与环境，既不知道当时
> 到底验了什么，也无法复跑。本目录给它们一个**仓内可寻址**的家。
> 决策理由：`.agents/notes/implemented/process/2026-11-24-acceptance-receipts-home.md`
> 入口登记：`docs/AGENTS.md` §1 的 Tier 表「验收收据」档。

## 三档分工（不要互相侵占）

| 落什么 | 家 |
|---|---|
| 决策理由（为什么这样、为什么不那样） | `.agents/notes/` |
| 任务状态与闭环证据指针 | `backlog/`（`evidence` 一行命令 + 收据路径） |
| **验收事实**（命令 / 环境 / 退出码 / 输出 / 结论） | `.agents/receipts/`（本目录） |

## 命名

`yyyy-mm-dd-<topic>.md`，`topic` 用 kebab-case，描述**被验收的对象**而不是动作
（例：`2026-11-15-gemini-e2e.md`、`2026-11-19-domestic-upstream-proxy-immunity-rollout.md`）。

## 最低四条（缺一条即不算收据）

1. **环境与时间**：节点/集群、镜像 `sha256` 或版本号、执行时刻（含时区）。
2. **可复跑命令**：原样贴出（含 `--noproxy '*'`、`--no-verify` 这类必要开关），并给出退出码。
3. **关键输出片段**：不要只写「通过」；贴能支撑结论的那几行（结构化字段/计数/断言名）。
4. **结论与残留风险**：写清哪部分**靠 review**、哪部分没验（诚实边界），不得把「没验」说成「已验」。

## 纪律

- 不建自动索引/生成物：检索靠 `ls .agents/receipts/` 与文件首行标题；真有消费者再立清单。
- 收据只追加、不改写：补验另开新文件并在旧文件首行加一行「后续见 …」。
- 收据不参与 `verify-note.sh`（它不是 ADR），格式约束靠 review —— 这条**没有门禁**。
- 存量 4 份历史收据（2026-11-15 ×3、2026-11-19 ×1）原貌保留，不回填已丢失字段。
