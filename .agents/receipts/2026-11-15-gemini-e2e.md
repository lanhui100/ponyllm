## 5. 验收过程记录（含验收者自身修正，保持可审计）

1. 首轮 `cargo test`：8 passed / 2 failed。
   - `a4` 失败原因是**验收者断言过严**：Anthropic 官方 thinking 块收尾确实会发 `signature_delta`（本网关 `signature:""`）。已将该 delta 类型纳入合法集合（并断言它只允许出现在 thinking 块索引 0）→ 通过。
   - `a6` 失败暴露 **O1**（function_call 缺 `output_item.done`）。经代码定位确认属于**跨协议的既有 chat→Responses 转换器行为**（`crates/ponyllm-protocol/src/translator/responses_stream.rs:844` `emit_terminal` / `:443` `finish_open`：function_call 项只在 `response.completed.response.output` 内完成，不单独发 done 帧），与 Gemini 无关；既有冻结契约 `crates/ponyllm-protocol/tests/red_protocol_stream_conformance_tests.rs:406-425`(R-SS-05..10) 只要求 message item 的 done。故 a6 改为断言 Gemini 侧必须保证的内容（added 帧带 call_id/name、`function_call_arguments.delta` 可重组、终态 output 内该 item 为 `completed`），并把缺口记录为 O1 上报，不修实现。
2. 真实 E2E 首轮 10/10 检查项中 `10`（thinking）失败，追查为**模型能力**（同 level 直连无 thought part），改为差分断言 + 增补 `10b`（高 level）→ 全通过（O4）。

## 6. 观测项 / 发现（不改实现，交裁决）

- **O1（既有、跨协议，非 Gemini 缺陷）**：Responses 流出参对 `function_call` 输出项**不发** `response.output_item.done`，只在终态 `response.completed.response.output` 内以 `status:"completed"` 出现；官方 OpenAI 客户端期望每个 item 有 done 帧。
  最小复现：`cargo test -p ponyllm-server --test gemini_acceptance_tests a6_` 时把断言换回"必须存在 `output_item.done` for function_call"，即失败；证据见 `responses_stream.rs:844`（`emit_terminal` 只调 `terminal_event`）。任何上游协议（Chat/Responses 原生）同样如此 → 归属 Responses 契约 owner，不属本 ADR 范围。
- **O2（与 ADR §6 假设不符）**：ADR 假定"400 `API_KEY_INVALID` 保持客户端 400 透出"。mock（`a8`）证明 400→400 路径成立；但**真实 `AQ.` 前缀新式 key 的非法值，Gemini 返回的是 401 `UNAUTHENTICATED`**（`ACCESS_TOKEN_TYPE_UNSUPPORTED`），网关按既有 `AuthInvalid` 映射下发 **502 `upstream_auth_failed`**（不 500、不重试放大）。建议 ADR 补注 key family 差异；若要"客户端可见 400"，需产品决策（不属本次验收改动）。
  最小复现：`curl -x http://127.0.0.1:8899 -H 'x-goog-api-key: AQ.Ab8…-INVALIDKEY' -d '{"contents":[{"role":"user","parts":[{"text":"hi"}]}]}' 'https://generativelanguage.googleapis.com/v1beta/models/gemini-3.1-flash-lite:generateContent'` → HTTP 401。
- **O3（配额冷却语义，单 key free tier 的现实约束）**：任一模型的日配额 429 会把**整把 key** 置入冷却，之后**其它模型**的请求在本地即被拒（`429 Local key pool exhausted … no schedulable keys`，无上游尝试）。即：单 free-tier key + 模型级 `fallbacks` 链在真实额度下无法被驱动（12f/12g、13/14 的 `__local_pool_429` 证据文件）。建议：多 key 或多账号，或在验收/演示前重启实例重置池状态。
  最小复现：打一次 `gemini-3.5-flash`（必 429 配额）后再打 `gemini-3.1-flash-lite` → 429 本地耗尽；重启实例后 `gemini-3.1-flash-lite` 立即 200（用例 14）。
- **O4（模型能力，非缺陷）**：`gemini-3.5-flash-lite` 在 `thinkingLevel:"low"` 下不产出 thought part（直连对照 `upstream_35lite_low.json`：无 `thought` part、无 `thoughtsTokenCount`），`high` 下产出（`upstream_35lite_high.json`：thought 1494 字符、`thoughtsTokenCount:648`）。网关行为与上游一致（低 level 不伪造 thinking 块）。副作用：Anthropic `thinking.budget_tokens ≤ 2048` 会被既有映射折成 `Low`，**thinking 演示/验收需 `budget_tokens > 8192`（→High）**。
- **O5（既有 thinking 线形）**：Anthropic thinking 块以 `signature_delta` 收尾，但 `signature` 为空串（chat 枢轴无上游签名）。官方字段存在但值缺失，SDK 一般可容忍；如需真实签名需持久化 Gemini `thoughtSignature`（ADR Risks 已提到），本次不计缺陷。
- **O6（出口风险实证）**：pproxy 冷启/抖动会表现为 ~31s 无响应（直连 curl 对照 HTTP 000 / 31.1s）；网关 3 次尝试后以 503 `upstream_unavailable` 收敛，不悬挂、不 500。与 ADR Risks 的"配置错误表现为 TTFB 超时"一致。

## 7. 未覆盖 / 局限

- 未覆盖：多模态（image/audio inlineData）、`responseSchema`/JSON 模式、工具多轮**回放**（`thoughtSignature` 回传）、`MAX_TOKENS`/`SAFETY` finishReason 的真实上游样本（仅 mock 覆盖映射逻辑）、Admin API 建 provider 与 `/v1beta/models` 后台探测（实现者 `gemini_admin_tests.rs` 已覆盖，本次按"独立"原则不复述）。
- 因免费层限额（每模型每日 20 次）与热门模型 503，E2E 只用了 `gemini-3.1-flash-lite` / `gemini-3.5-flash-lite` 两个实测可用模型；`gemini-3.6-flash`/`gemini-3.8-flash`/`gemini-3.7-flash` 按 Lead 指示与实测状态未作为功能用例模型。
- 复跑成本提示：本收据的 10 个功能用例共消耗 `gemini-3.1-flash-lite` 约 8 次、`gemini-3.5-flash-lite` 约 4 次（含 10b/14/16/17），重跑前确认当日剩余额度。
