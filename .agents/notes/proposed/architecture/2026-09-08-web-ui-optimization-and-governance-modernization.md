# Agent Note: Web 端 UI 深度优化与模型治理重构

Status: proposed

## Problem

当前 PonyLLM Web 控制台存在若干视觉与交互体验问题，并伴随安全敏感信息暴露隐患：
1. 顶部导航路由排序不符合日常治理习惯（模型管理排在可观测性之后）；
2. 模型治理页面存在多套重复视图（`全部服务商` 已经三合一聚合了服务商、模型与密钥，而独立的 `模型字典` 与 `密钥池` 标签造成概念冗余与操作割裂）；
3. 服务商卡片展示明文 `base_url`，部分第三方平台会在 URL Query 中附带 token 参数，容易导致凭证泄漏；且列表与卡片各回表徽标使用淡浅底色，反差对比度低；调度策略未映射通俗中文名称；
4. 密钥与模型列表在服务商展开后直接平铺展示，信息过载，缺少按需独立折叠能力；
5. 服务商层保留了过时的单价配置面板，与模型级计费发生职责错位；且服务商缺少原生协议与多协议覆盖端点配置界面；
6. 模型编辑器视觉风格与上下文选项滞后；多模态输入与输出能力合并混杂；缺乏底层协议便捷切换；
7. 可观测性大盘缺乏直观反映最近调用 metrics 及近 24 小时真实处理速率（t/s）的聚合组件。

## Proposal

本提案对 Web 端与配套接口实施 10 项系统性优化，并分 4 个阶段有序交付：
1. **导航与视图简化**：将 NavBar 模型管理移至可观测性前；清理 `GovernanceView` 冗余的“模型字典”与“密钥池” tab；
2. **安全脱敏与视觉强化**：服务商卡片使用暖橙色图标，彻底去除名称下明文 base_url，缺省统一为 `https://tokens.ponyjob.top/v1`；全局重构 `UiBadge` 为深色高反差底反白字体；建立策略通俗中文字典（如 `round_robin` -> `轮询`）；
3. **层次收敛与协议多选**：将“密钥凭证”与“挂载模型”更名为“密钥”与“模型”，各自默认折叠；移除服务商高级计费参数；在密钥同级增加平铺非下拉的模型协议多选器，支持按协议覆盖 base_url；
4. **模型编辑器与模态解耦**：模型选择器采用暖黄色色阶 200 底色（`bg-amber-200`）；上下文预设收敛为 `256K`、`512K`、`1M`；输入与输出模态彻底拆分为独立选择器；高级设置支持 3 种底层协议选项与独立 base_url；更新按钮文案改为“更新”；模型分级徽标显示中文（如 `主力`、`旗舰`、`轻量`）；
5. **Dashboard 6 柱 Uptime 组件**：新增 6 柱 Uptime bar 微组件，每根柱子表达最近调用的 metrics（状态、延迟、流速），并展示最近 24 小时内统计的 t/s 速率。

## Alternatives considered

1. **完全重写 Web 控制台页面 vs 渐进式组件重构**：
   - 完全重写耗时长，可能破坏已有的只读治理安全栅栏与 412 乐观锁机制；
   - 采用渐进式组件重构，复用已有状态管理与测试用例，风险最低且迭代迅速。
2. **纯前端掩盖 URL vs 根治去除 URL 明文**：
   - 若仅在前端打码，仍可能在 DOM 或开发者工具中被直接窥见；
   - 彻底从服务商名称展示区移除 base_url，默认统一走内部反代网关地址 `https://tokens.ponyjob.top/v1`，彻底根绝泄漏。
3. **模态依然使用单一字段 vs 解耦为 input_types 和 output_types**：
   - 单一字段无法表达“纯文本输入但可输出图像/音频”等混合模型能力；
   - 严格解耦为输入模态与输出模态，且前后端对齐，符合大模型行业演进标准。

## Acceptance criteria

1. NavBar 导航项顺序为 `Dashboard` -> `模型管理` -> `可观测性`。
2. 模型治理页面仅保留 `全部服务商` 和 `全局策略`，无多余子 tab。
3. 服务商卡片前置图标为暖橙色；去除名称下明文 URL；所有回表 Badge 采用深底反白高对比风格；策略显示通俗中文。
4. “密钥”与“模型”两部分均可折叠且默认收起；卡片移除服务商单价配置；同级具备模型协议多选胶囊及对应选填 base_url。
5. 模型选择器背景为暖黄 200；上下文选项为 256K、512K、1M；输入/输出模态独立；高级协议 3 选 1 带 base_url；按钮文案为“更新”；分级徽标显示中文。
6. Dashboard 呈现 6 柱 Uptime bar 组件，清晰展示最近调用指标与 24h 均速 (t/s)。
7. 前端 Vitest / TypeScript / Oxlint 及后端 Cargo 测试 100% 通过。

## Risks

1. **测试断言破坏**：移除 models/keys tab 与更改导航顺序可能会打破已有的端到端测试选择器，需要同步更新测试用例断言。
2. **协议回显向后兼容**：新增的模型模态与服务商协议字段需保持向前向后兼容，确保历史老配置依然平滑加载。
