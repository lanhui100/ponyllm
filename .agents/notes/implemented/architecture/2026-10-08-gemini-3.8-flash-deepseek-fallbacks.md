# Agent Note: Gemini 3.8 Flash 系列接入 DeepSeek 级联容灾 Fallbacks 架构

Status: implemented

## Problem

在当前的网关拓扑中，`gemini-3.8-flash` 及其衍生变体（包括 `gemini-3.8-flash-high`、`gemini-3.8-flash-tiered` 等）作为默认的主力低延迟多模态与日常推理模型，主要依赖上游 Antigravity 代理链路。然而在实际高并发生产与编码调用中，面临以下架构与可用性挑战：
1. **上游服务抖动与空响应（Empty STOP）异常**：Google/Antigravity 逆向代理偶发 403 额度冻结、429 速率限制或连续触发 3 次无有效 Payload 的空 STOP 早期收敛，直接阻断客户端调用。
2. **缺乏同级容灾逃生通道**：在没有配置模型级 `fallbacks` 的情况下，当 Antigravity 上游供应商实例全部耗尽或故障熔断时，网关直接向客户端抛出 502/503 错误，造成用户端任务中断。
3. **思考强度与变体模型退化割裂**：`gemini-3.8-flash` 存在带后缀的思考强度变体（`-high`, `-tiered`），若仅对基础模型配置灾备，在衍生变体被调用且故障时将无法平滑触发多级降级。

## Decision

1. **为 Gemini 3.8 Flash 建立双级 DeepSeek 级联兜底拓扑**：
   - 主模型序列：`gemini-3.8-flash`、`gemini-3.8-flash-high` 与 `gemini-3.8-flash-tiered`。
   - 级联灾备链统一声明为有序队列：`["deepseek-v4-flash", "deepseek-flash"]`。
   - 第一级兜底 `deepseek-v4-flash`：承接高频极速推理与上下文请求，保证响应速度与编码指令遵循度。
   - 第二级兜底 `deepseek-flash`：作为底层稳定保底线路，在上游 V4 变体不可达或配额受限时提供终极高可用保障。

2. **多变体继承与路由解析规范**：
   - 在模型规范（`model_specs`）中显式为基础模型 `gemini-3.8-flash` 以及变体 `gemini-3.8-flash-high`、`gemini-3.8-flash-tiered` 赋予相同的 `fallbacks` 数组。
   - 网关路由解析器（`resolve_routed_targets`）在解析主模型及其思考变体时，递归展开保底模型的目标候选集，形成 `[primary_target, fallback_target_1, fallback_target_2]` 的加权候选链。

3. **空 STOP 与上游故障触发机制契约**：
   - 触发条件：当主模型遭遇网络不可达、HTTP 429/403/5xx 错误、或者连续遭遇 3 次确定性空 STOP 终止时，触发网关单次请求内的物理模型迁移。
   - 去重与防环：依赖现有 `dedup_routed_targets` 算法，在遍历主链路与 DeepSeek 兜底链路时自动剥离同名重复上游，保证故障转移干净且无死循环。

## Alternatives considered

1. **方案 A：仅在上游 Provider 级做故障转移，不配置跨模型 Fallbacks**：
   - 优势：无需跨模型对齐协议与思考参数。
   - 劣势：Antigravity 服务商故障通常是全账号或全集群级别的；在同一 Provider 内换 Key 无法解决 Gemini 平台级不可用或模型被风控的问题，必须跨模型跨供应商切到 DeepSeek。
2. **方案 B：降级目标直接切入大模型旗舰级 `deepseek-chat` 或 `deepseek-reasoner`**：
   - 优势：推理能力更强。
   - 劣势：延迟与 Token 成本大幅增加，且与 `gemini-3.8-flash` 作为“极速轻量/交互型推理”的定位不符。选用 `deepseek-v4-flash` 和 `deepseek-flash` 能够在吞吐量、时延和成本上保持最佳平衡。
3. **方案 C：仅在客户端或 SDK 侧配置捕获重试**：
   - 优势：网关内部状态简单。
   - 劣势：客户端实现参差不齐，且无法利用网关已有的连接池、空 STOP 探测状态机与上游熔断感知机制，用户体验较差。

## Consequences

1. **正向收益**：
   - 极大提升了 `gemini-3.8-flash` 及其高思考变体的整体可用率（SLA 从单点 Antigravity 提升至跨云灾备）。
   - 客户端面对 Antigravity 封锁或空 STOP 抖动时无感切换，透明由 DeepSeek Flash 系列代偿输出。
2. **潜在风险与应对**：
   - 跨模型多模态能力差异：Gemini 支持图像输入，而纯文本 DeepSeek 兜底可能不支持图像输入；对于纯文本与代码补全场景完全兼容，多模态场景在无法处理时按协议标准返回明确的格式校验提示。
