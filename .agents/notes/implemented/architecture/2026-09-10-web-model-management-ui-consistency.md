# Agent Note: Web 模型管理与编辑页面一致性视觉体验重构

Status: implemented

## Problem

在 Web 控制台的模型管理页面（`GovernanceView` / `ModelSubSection`）与模型新建/编辑表单中，存在多处 UI 割裂、视觉不一致与视觉层级混乱的问题：
1. **图标颜色混乱不一**：模型列表标题使用 `indigo-500`，入模态图标使用 `slate-500`，出模态图标使用 `emerald-600`，思考强度使用 `purple`，各种杂色在单行内混杂，缺乏统一的层级感和品牌色彩秩序。
2. **徽标（等级、思考强度等）位置不统一**：模型分级徽标、上下文容量、模态图标组、协议徽标、采样参数/价格微标、思考强度微标在模型行内左右乱跳；思考强度微标被孤立在右侧尾部，分级徽标和上下文又在最前，导致关键特征信息无法聚合扫描。
3. **上下文（Context）大小写混用**：模型列表展示为 `128k` / `256k` / `1m`，按钮展示为 `256K` / `512K` / `1M`，占位符或输入框为 `256k`，缺少规范的统一大写或规范缩写格式（统一为 `256K`, `512K`, `1M`, `200K`）。
4. **图模型的输入与输出图标过小且与行高脱节**：模型列表行中模态图标仅为 `12px`，在 14px 正文字阶和 36px+ 行高下显得非常微小、辨识度极低，且文本指示符（`入:` / `出:`）与微小图标挤在一起，与周边徽标高度严重不协调。
5. **模型编辑页面不同 Switch 配色割裂**：模型分级（Tier）使用了亮刺眼的黄色底色（`bg-amber-200/90`），而上下文预设（Context）使用了浅灰色（`bg-slate-200/60` 或 `bg-slate-100`），思考强度（Thinking Effort）使用了浅蓝灰底色（`bg-slate-100/90`），一个表单内出现三种不同色调的 switch/分段选择器底色，极其凌乱杂乱。

## Decision

针对上述问题，构建统一的模型展示与编辑设计规范并实施：

1. **色彩层级与图标系统规范化**：
   - 统一基础功能图标与辅助图标颜色体系，以优雅的中性板岩冷灰（`slate-400` / `slate-500`）作为基底，避免非必要的杂色冲击；
   - 统一多模态输入/输出的语义指代，使用克制的板岩青/中性灰胶囊组件包裹，使输入与输出模态拥有对称、稳重的视觉平衡；
   - 思考强度微标归入紫色系/琥珀系徽标规范，并与模型属性紧邻摆放。
2. **模型行内徽标与元数据对齐与次序重塑**：
   - 统一行内信息结构：`[模型标题/显示名称] [分级 Badge] [思考强度 Badge (若开启)] [上下文胶囊] [输入/输出模态胶囊组] [协议/高级 Badge]`；
   - 将“思考强度”徽标移至“模型分级”右侧，紧密跟随核心能力定义，确保用户在一瞥之内掌握模型的认知等级与分级；
   - 保证徽标高度、行内间距（`gap-2`）及基线统一，消除错落参差。
3. **上下文（Context Window）格式化与标准化**：
   - 新增统一格式化工具 `formatContextWindow(val)`，自动将 `k`、`m`、`g` 等单位规范化为符合行业标准的大写 `K`、`M`、`G`（如 `128k` -> `128K`，`1m` -> `1M`），在展示层完全统一，彻底消除大小写混用。
4. **多模态图标尺寸与容器视觉强化**：
   - 将模态图标尺寸从 `12px` 提升至 `14px`，并包裹在圆角微透明胶囊标签内（高度 `20px`），与模型分级 Badge 高度（`20px`）和上下文标签完全等高对齐；
   - 采用精致的分割符与清晰的模态图标微交互，确保图片、视频、音频、文本图标清晰可辨。
5. **模型编辑表单 Switch/分段选择器配色大一统**：
   - 彻底废除刺眼突兀的黄色（`bg-amber-200`）分段选择器底色；
   - 统一所有分段选择器（模型分级 Tier、上下文 Context、思考强度 Thinking Effort、协议选择）为一致的现代浅底色卡片分段底衬（`bg-slate-100/90 border border-slate-200/70`）；
   - 选中态统一为：纯白底色（`bg-white`）、悬浮柔和投影（`shadow-2xs` 或 `shadow-xs`）、深色文字（`text-slate-900` 或主色强调），未选中态统一为 `text-slate-600 hover:text-slate-900 hover:bg-white/50`，保证整个表单所有 switch 风格完全统一、和谐呼吸。

## Alternatives considered

1. **保留分级黄色但调低饱和度（如 amber-100/50）**：
   - 缺点：即便调低饱和度，同一个表单内分级是黄色、上下文是灰色、思考是蓝灰，依然是三种不同的背景色彩，无法根治“不同 switch 配色方案导致凌乱”的本质问题。统一为同一中性浅底色卡片底衬是现代设计系统（如 Apple HIG、Tailwind UI、Linear 等）的最佳实践。
2. **在行内模型列表保留 12px 极小图标并移除文字**：
   - 缺点：在 14px 基准字阶与 40px 行高下，12px 过于弱小几乎难以被辨识；提升到 14px 并配以等高药丸胶囊是最具可用性与美感的折中。

## Consequences

1. **视觉一致性完备**：模型管理页面的行内元数据排列井然有序，上下文大小写完全规范统一为大写，多模态图标大小适度且与行高完美协调。
2. **表单质感大幅提升**：模型新建与编辑表单彻底告别了“黄灰混杂”的混乱 Switch 配色，所有选择器使用一致的高级分段控制器样式，界面整洁利落。
3. **测试向后兼容**：针对更新后的分段选择器样式更新端到端测试断言，确保自动化流水线 100% 绿灯。
