# Agent Note: 热缓存前缀追踪、429 自动避让与人话终端交互体验

Status: implemented

## Decision

1. **分片无锁热缓存追踪 (`HotCacheTracker`)**：
   - 采用 64 分片无锁槽位，存储 24 字节紧凑签名（`u64` Hash + `u32` TTL，零 String 堆分配，全局硬顶 10,000 条，内存严格控制在 500KB 以内）；
   - 设定最小前缀字符数 $\ge 1024$ 字符（或包含 System Prompt）才触发 Hash 追踪，短文本跳过走常规负载，杜绝单点打爆；
   - 5 分钟超时物理淘汰，同一会话再次到达时判定为热缓存，经济打分享受 `cached_price` 折扣。
2. **CAS 无锁 EWMA 与客户端主动中断（Drop）防投毒**：
   - 采用 `AtomicU64` 浮点位变换完成无锁 EWMA 迭代，消除全局锁颠簸；
   - 客户端主动断开（`ClientAborted`）严禁计入有效 TPS 样本，短响应（$<10$ tokens）不更新全局 TPS，防止度量投毒导致优质节点被误降级。
3. **429 智能时间戳解析、双通道规范错误渲染与安全退避**：
   - 解析 429 Header 时区分相对秒数与绝对 Unix 时间戳（`secs > 1_000_000_000`），并硬设 5 分钟安全钳位上限（`clamp(1, 300)`），杜绝 54 年锁定死锁；
   - 缺失 Header 时采用基底 3s + 指数退避（3s, 6s, 12s... max 60s）；
   - 错误响应按路由入口分别严格渲染 OpenAI（`error.code`）与 Anthropic（`type: "error"`）规范格式。
4. **前端人话大白话交互**：
   - CLI 提供 `ponyllm strategy` 查看与设置；
   - 启动面板与 TUI 看板彻底杜绝工程黑话，使用“💰 省钱模式”、“⚡ 极速模式”、“🛡️ 稳定模式”等通俗直观词汇。

## Alternatives considered

- **全局互斥锁 LRU 缓存**：
  - *否决理由*：高并发下读命中亦需修改链表指针，导致 Tokio Worker 线程全局写锁自旋死锁，吞吐雪崩。

## Consequences

- 保证在高并发压测与网络抖动下具备极高的鲁棒性与超低延迟；
- 彻底解决长会话成本与客户端反序列化兼容性。
