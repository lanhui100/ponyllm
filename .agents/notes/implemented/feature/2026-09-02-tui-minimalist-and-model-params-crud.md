# Agent Note: TUI 极简界面设计、Provider 与 Model 增删改查及模型参数治理

Status: implemented

## Problem

1. **界面视觉冗余与大边框压迫感**：当前 TUI 采用了大量四面包围的圆角粗边框（Borders::ALL + Rounded），割裂了屏幕空间，信息密度低，视觉繁复，缺乏现代极简排版美感。
2. **缺乏 TUI 内置 CRUD 闭环能力**：当前 TUI 面板为纯只读展示，用户在看板中无法直接添加、编辑、删除 Provider 和 Model，必须退回到 CLI 命令行或者手动编辑配置文件，交互链路被打断。
3. **模型配置缺乏丰富参数维度**：模型实体仅记录名称字符串，无法配置大模型关键运行时参数：
   - 上下文窗口容量（Context Window，如 1M、200K、128K 等，默认 1M）；
   - 最大输出 Token 限制（Max Output Tokens，如 32K、64K、8K 等，默认 32K）；
   - 输入模态类型（Input Types，默认文本，多选支持图像、视频、音频）；
   - 输出模态类型（Output Types，默认文本，多选支持图像、视频、音频）。

## Decision

1. **TUI 界面极简风格重构（Minimalist & Zen Layout）**：
   - 全面去除封闭四面包围粗大边框，改用排版对齐、字体粗细（Bold）、颜色层级、点标指示（● / ○）与微细分割线（─、│、Borders::BOTTOM）划分区域；
   - 顶部 Header 改为轻量导航条，高亮当前 Tab，右侧直观展示网关在线状态与监听地址；
   - Tab 2 提供商 & 模型看板重构为左右双栏联动视图（左栏 Provider 清单，右栏对应模型的详细参数矩阵与规格卡片）。
2. **TUI 交互式 Provider / Model 增删改查（CRUD）模态框**：
   - **Provider CRUD**：
     - （添加）：弹出新建 Provider 表单；
     - （编辑）：编辑选中 Provider 的 Base URL、默认模型及调度策略；
     - d（删除）：带安全确认提示的删除。
   - **Model CRUD**：
     - （添加模型）：配置模型名、上下文（默认 1M）、最大输出（默认 32K）、多选输入/输出模态；
     - （编辑模型）：修改选中模型的参数；
     - d（删除模型）：安全删除非默认模型；
     - s（设为默认）：一键将当前选中的模型设为 Provider 的默认主模型。
   - 变更后自动原子持久化至配置文件，状态栏提供即时操作反馈。
3. **多维模型参数配置架构（ModelConfig）**：
   - 在 ProviderSection 中新增 model_configs: Vec<ModelConfig>，定义包含 context_window、max_output、input_types、output_types 的结构体；
   - 提供向后兼容与默认值自动补齐机制，确保老配置文件与只传模型名的场景无缝兼容。

## Alternatives considered

- **全屏独立页面而非模态弹出框进行表单输入**：
  - *否决理由*：全屏切换会导致用户丢失上下文（看不清当前是为哪个 Provider 配置模型），模态居中框更轻巧直观，编辑完按 Esc/Enter 即可瞬间返回看板。
- **将输入/输出模态设计为逗号分隔的自由文本输入**：
  - *否决理由*：自由输入易出现拼写错误（如 txt / img 等），改为固定多选标签（文本、图像、视频、音频）按数字或空格一键切换更严谨高效。

## Consequences

- TUI 界面显著提升通透感与现代美感，终端字符利用率大幅提高；
- 用户可以在 TUI 中完成所有网关路由及模型参数的全生命周期管理；
- 模型元数据具备标准化多模态与上下文规格，为后续高级路由与能力协商打下基础。
