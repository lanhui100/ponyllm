# Web 端 Token 列表交互与凭证轮换优化

Status: implemented

- 日期：2026-10-11

## Context

在 Web 管理端“我的 Token”页面（`/tokens`）中，原有的交互存在以下可用性与安全性痛点：
1. 页面默认直接内嵌展示创建表单，占据大量垂直视野，与列表浏览流存在割裂；
2. Token 创建与轮换操作后的明文展示形式不统一，缺乏一键复制和明确的安全提示；
3. 原列表操作按钮文案使用了“旋转”，未能准确贴合主流凭据治理术语“轮换（Rotate）”；
4. 后端执行 Token 轮换（POST `/api/user/tokens/{key_id}/rotate`）时，网关内存状态中的 `gateway_keys` 未实时同步更新，导致旧 Token 未即时失效阻断。

## Decision

1. **页面交互结构优化**：
   - 移除列表顶部的内嵌创建表单；
   - 在 Token 列表底部增设直观的“新增 Token”按钮（带 plus 图标）；
   - 点击“新增 Token”唤起模态弹窗（Modal），表单校验与创建动作在弹窗内闭环，保存后自动关闭。

2. **凭据展示与复制体验**：
   - 无论是新 Token 创建成功还是旧 Token 轮换成功，均唤起统一的明文凭证展示模态弹窗；
   - 弹窗内突出“明文仅展示一次”与“旧凭证已即刻作废失效（针对轮换）”安全提醒；
   - 引入带复制状态切换图标（copy / check）的复制按钮，支持一键剪贴板复制及降级兼容。

3. **术语与后端轮换一致性**：
   - 将“旋转”按钮统一改称为“轮换”；
   - 在后端 `handle_user_tokens_rotate` 保存配置文件后，实时同步写入内存 `state.config.write().gateway_keys`；
   - 编写契约验收测试，物理验证轮换后旧 Token 立即返回 401 Unauthorized，新 Token 正常返回 200 OK。

## Alternatives considered

- **保持内嵌创建折叠面板**：虽然减少初始占用，但创建与查看主次不清，多模态输入交互不够聚焦，因此选用模态弹窗。
- **轮换仅弹 Toast 不展示新 Token**：由于 Token 明文出于安全考虑不进行持久化存储且仅能获取一次，若仅 Toast 容易造成误触丢失，弹窗强交互是最佳实践。

## Consequences

- 提升了用户自助 Token 的操作便捷性与安全性；
- 杜绝了凭据轮换时的内存与持久化不一致隐患；
- 前端测试用例 206 项全绿，包含新增的 `TokensView.test.ts` 交互流测试。
