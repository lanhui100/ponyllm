# Agent Note: status 分区划线与 TUI 弹窗收窄及模型默认值对齐

Status: implemented

## Problem
`ponyllm status` 输出过于简陋，缺少分区间视觉分隔，可读性差；TUI 提供商添加/编辑弹窗宽度过大且选择器文案过长，在 80 列终端下被截断；模型添加/编辑的等级选择不易见，且上下文/最大输出与价格默认值不符合当前 1M/32K/0 的预期。

## Decision
status 输出按服务状态、连接、提供商、用量、提示分节，每节上下使用 `──────────────────────────────────────────────────` 灰色划线分隔，保留 NO_COLOR 与 TTY 着色兼容。
TUI 将提供商弹窗收窄至 72 列、模型弹窗收窄至 76 列、Key 弹窗收窄至 68 列，所有弹窗段落启用 `Wrap` 自动换行；计费/协议/梯队/模态选择器改用短标签（计费/协议/梯队/输入/输出，`1:F旗舰/2:S标准/3:L轻量`，`resp/anth` 缩写，`文Txt/图Img/视Vid/音Aud` 紧凑模态），底部统一提示数字键与空格切换。
模型默认值统一为上下文 `1M`、最大输出 `32K`、输入/缓存/输出价格 `0`：CLI 解析默认值、`ConfigFile`/`ModelSpec` 的 serde 默认、TUI 新建初始值与空值回退均对齐；TUI 提供商新建价格初始值与空值回退同步为 `0`，编辑态继承空价格回显为 `0`；等级选择保持 `Flagship/Standard/Light` 三档并通过收窄与换行确保可见。

## Alternatives considered
- status 沿用极简无划线短行：否决，信息密度虽低但分节缺失，用户明确要求划线区分。
- 恢复旧版全框 `╔═╗` 大看板：否决，边框在窄终端易错位，且与当前极简风格冲突；轻量划线分隔兼顾可读与兼容。
- 保持弹窗 84/88 列并仅加换行：否决，80 列终端下左右仅剩 1 列边距，仍显拥挤；收窄至 72/76 列配合短标签才能彻底消除截断。
- 模型价格保持空即继承：否決，用户明确要求默认为 0，空回退补 `Some(0.0)` 使新建模型显式免费，避免继承提供商按量价造成意外计费。

## Consequences
- `cargo test -p ponyllm-cli` 全绿；`cargo clippy -p ponyllm-cli --tests` 仅存量告警；`ponyllm status` 离线冒烟确认四节划线正常。
- 存量显式 `128K/4K` 测试数据保持不动，仅 CLI 默认解析与配置默认回退改为 `1M/32K`；`cli_tests` 对应断言同步更新。
- TUI 模态紧凑断言更新为 `[x]1:文Txt` 无空格格式，总字符预算 65 列保持。
