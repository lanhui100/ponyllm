# Agent Note: status 输出极简重排

Status: implemented

## Problem

`ponyllm status` 当前用整宽边框表格输出全部信息，存在三个阅读问题：一是边框与对齐填充挤占宽度，窄终端下换行错位；二是装饰符号与工程术语混杂（遥测、网关凭证、上游密钥池、TTFT、export 等），普通用户需要翻译才能理解；三是色彩与表情使用无节制，状态、警告、提示混用多种强调，重点不突出。

## Decision

把 `handle_gateway_status` 的输出改为无边框、无表格的分段短行：

- 顶部四行直接给出结论：状态、地址、配置、策略，之间不加空行装饰。
- 下方按连接、提供商、用量分组，组名独占一行，组内条目统一两个空格缩进，组间空一行分隔。
- 文案只说用户能直接行动的事：状态只说运行中或未运行；策略只说省钱优先、速度优先、稳定优先、均衡；密钥只说值或未设置；提供商只说默认模型与有无密钥；用量只说共几次请求、成功几次、共用多少 Tokens，没有请求时直说还没有请求。
- 色彩只保留一处：状态值在终端下运行中用绿色、未运行用红色，其余文字不着色；设置 `NO_COLOR` 或非终端时不输出转义码。
- 去掉边框制表符、表情符号、对齐填充与 `export` 示例，连接信息只给地址与密钥两个可复制的值。

## Alternatives considered

- **保留边框表格，只收窄列宽与删减列**：
  - *否决理由*：表格本身要求预估列宽，中文全半角混排下必然错位；删列不能解决术语与装饰问题，只是把拥挤藏起来。
- **引入第三方着色库做多彩分级输出**：
  - *否决理由*：新增依赖只为装饰不值得；多色分级与本次克制用色的目标相悖，重点会被颜色淹没。
- **status 中继续保留完整 `export` 示例**：
  - *否决理由*：`ponyllm auth` 已承载复制即用的接入示例，status 重复展示会拉长输出；status 只保留地址与密钥的值，用户照着填即可，不断操作链路。

## Consequences

- 窄终端下不再错位，输出可直接复制地址与密钥。
- `NO_COLOR=1` 或管道重定向时输出为纯文本，脚本解析更稳定。
- 靠 review：文案是否足够通俗、无工程术语残留。
