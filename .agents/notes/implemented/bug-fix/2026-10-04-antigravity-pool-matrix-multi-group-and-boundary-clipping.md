# Agent Note: Antigravity 算力池矩阵多组垂直排列与边缘防切割优化

Status: implemented

## Problem
在 Web 端 Dashboard 中，Antigravity 算力池热力方块矩阵目前固定为单组 5 行展示（`grid-rows-5 grid-flow-col`）。当用户接入大量账号或需要更直观的分组浏览算力池容量时，单组 5 行横向排列无法满足分层视图需求；用户期望每 5 行为一组、垂直排列，并增加新的一组（共 2 组，每组 5 行）。
此外，矩阵容器设置了 `overflow-hidden` 且紧密贴合，当用户悬浮（`hover:scale-125`）或点击选中（`scale-110 ring-2`）边缘方块（顶部、底部、最左或最右）时，方块放大部分会被父级容器或周边视口溢出切割，破坏视觉完整性。

## Decision
1. **多组 5 行垂直排列**：
   - 将原单组 `grid-rows-5` 矩阵升级为支持多组（当前展示 3 组）垂直排列。
   - 每组固定 5 行，按列流动（`grid-rows-5 grid-flow-col`），各组独立计算总槽位（每组 `totalColumns * 5`，3 组共 `totalSlots = totalColumns * 15`），上下组之间留出清晰优雅的垂直间距。
   - 数据槽位按顺序填充分配至各组，未占满槽位填充预留占位方块。
2. **边缘方块点击与悬浮防切割**：
   - 为矩阵网格容器增加安全内边距（`p-1`）并去除生硬截断，为 `hover:scale-125` 与选中 `scale-110 ring-2` 留出足够的扩散空间（±4px~6px 渲染余量）。
   - 保持方块在聚焦或激活时 `z-10` 层级提升，确保边缘方块放大时不会被父级容器边框或兄弟元素遮挡裁切。

## Alternatives considered
1. **维持单组 10 行并单网格渲染**：
   - 破坏了原本 5 行一组的视觉节律与 GitHub 热力图心智，无法体现两组在垂直方向上的独立分组语义。
2. **完全依赖 transform-origin 动态计算偏移**：
   - 逻辑极其脆弱且在不同屏幕宽度、动态自适应列数下易引发抖动。通过外层留足扩散 padding + 适度可见溢出是更稳健纯粹的现代 CSS 方案。
