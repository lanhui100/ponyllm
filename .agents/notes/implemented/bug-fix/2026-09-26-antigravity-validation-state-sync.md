# Agent Note: Antigravity 验证拦截状态同步

Status: implemented

## Problem

Google Antigravity 返回 `403 VALIDATION_REQUIRED` / `Verify your account to continue` 时，网关此前把它当作未知 403 短暂冷却；Web 算力池方块仍可能沿用上一次成功探测的额度快照显示绿色。绿色额度只能说明历史探测时有余量，不能代表当前账号已经通过 Google 验证并可调度。

## Decision

将 Google 账号验证拦截识别为需要人工处理的账号级不可用状态，并让管理端探测失败结果覆盖旧的配额快照：

- 上游 403 body 命中验证拦截签名时，归入账号策略隔离路径，避免继续把账号当作可用账号调度。
- Antigravity 管理探测保留失败与错误码，不再把 quota fetch 失败包装成成功；探测失败会清理该账号前端持久化的旧 quota 结果。
- 算力池方块优先展示当前探测失败/验证状态，显示为不可用，而不是继续使用过期绿色额度。
- 验证完成或重新授权后，下一次成功探测重新写入额度并恢复显示。

## Alternatives considered

- **只延长未知 403 冷却时间**：只能减少重试，不能解释账号需要验证，也不能修复 Web 端沿用绿色旧快照的问题。
- **只改 Web 方块颜色**：无法阻止网关继续调度被 Google 拦截的账号，且刷新页面后仍会回到错误状态。
- **只依赖 quota bucket 为零判定**：验证拦截与额度耗尽是不同信号，403 验证错误可能发生在额度仍充足时，不能混为一谈。

## Consequences

验证拦截账号会从正常调度集合中移出，直到人工完成 Google 验证或重新授权；Web 状态与最近一次探测结果一致。旧 quota 快照不会在失败后继续误导用户。该状态需要人工动作恢复，不能靠等待额度重置自动恢复。
