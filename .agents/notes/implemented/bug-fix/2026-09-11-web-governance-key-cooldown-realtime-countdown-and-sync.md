# Agent Note: Web 模型管理密钥冷却徽标实时倒计时与自动状态对齐

Status: implemented

## Problem

在 Web 控制台的模型管理视图（`/governance`）中，当 Antigravity 或其他服务商密钥触发 429 配额限制进入冷冻期后，界面展示的冷却徽标及剩余时间（如「冷却中 8分后解冻」）存在静态固化与状态脱节的问题：

1. **页面缺失周期轮询与可见性驱动的同步机制**：`GovernanceView` 与 `useAdminConfig` 仅在初次进入（`onMounted`）或手动点击“刷新”按钮时调用 `fetchAll()`。当密钥在服务端冷却到期、恢复为 `active` 并且已经在处理线上流量时，前端页面因无自动轮询而长期停留在旧快照中，误导管理员以为密钥仍处于不可用或故障状态。
2. **倒计时时间为不可变静态数值**：`KeySubSection.vue` 中 `cooldownRemainingSecs` 直接读取服务端返回的 `k.cooldown_remaining_secs`。该字段在首次请求到达后即固定不变，没有客户端秒级流逝驱动，导致哪怕经过数十分钟，页面依旧显示初次加载时的“8分后解冻”。
3. **倒计时到期后缺少自动对齐触发**：当密钥的实际解冻时刻已经过去，由于没有监听本地倒计时归零，页面无法自动向后端同步最新连接池状态。

## Decision

1. **`KeySubSection.vue` 引入秒级本地响应式时钟与动态倒计时换算**：
   - 记录快照抓取时的本地基准时间戳，或使用局部响应式 `now` 时钟信号；
   - 统一计算剩余秒数：以 `k.cooldown_reset_at` 目标时间戳（若有时）或者以服务端抓取时的 `cooldown_remaining_secs - 本地逝去秒数` 动态递减，保证界面每秒平滑流逝更新；
   - 当检测到某个密钥倒计时从正数递减到 0 时，自动发出或触发一次静默对齐刷新，使状态及时转为 `active`。
2. **`useAdminConfig` / `GovernanceView` 接入前台安全轮询（后台标签暂停）与全局停止注册**：
   - 增加受控的自动轮询机制（默认间隔 5s~8s），在用户停留在治理页面且页面可见（`document.visibilityState !== 'hidden'`）时轻量同步后台资源状态；
   - 接入路由 `onStopPolling` 守卫与组件卸载清理，401 拦截或页面跳出时可靠销毁定时器；
   - 当用户正在本地表单新建/编辑服务商或模型时，跳过对表单状态的覆盖，保证治理操作的人机交互不受后台拉取干扰。

## Alternatives considered

- **方案 A：仅依赖 WebSocket / SSE 全局广播密钥状态变更**：虽然最实时，但目前后端 `/api/admin/keys` 为标准 RESTful CUD 架构，为了密钥状态变更专门重写管理端长连接通道会显著扩大系统复杂度与攻击面；且目前遥测流和治理控制台职责解耦清晰。故优先采用高内聚轻量的客户端动态倒计时 + 可见性感知轮询，否决。
- **方案 B：仅在倒计时计算中用 `cooldown_reset_at - Date.now()`，不加轮询**：若服务端因人工干预或配置热重载提前解除冷却，纯客户端计算无法感知真实服务端状态；且缺乏到期拉取时仍无法更新 `k.state` 字段（仍为 `cooling_down`），否决。
- **方案 C（采纳）**：客户端本地动态倒计时平滑递减 + 归零对齐 + 页面可见期后台安全轻量轮询，端到端解决不实时、不准确的痛点。

## Consequences

- 密钥冷冻徽标后的剩余时间将每秒动态递减显示（例如「8分后解冻」→「7分59秒后解冻」）；
- 密钥冷却到期或已在使用中时，模型管理页面将在数秒内自动感知并消隐「冷却中」徽标，恢复为就绪状态，无需手动刷新；
- 离开页面或标签页置入后台时自动挂起轮询，零多余网络开销与内存泄漏风险。
