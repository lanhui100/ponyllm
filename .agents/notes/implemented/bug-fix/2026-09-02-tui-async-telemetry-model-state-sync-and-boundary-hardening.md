# Agent Note: TUI 异步遥测解耦、模型状态一致性与边界加固

Status: implemented

## Problem

在对 TUI 极简界面与 CRUD 体系的对抗代码审计中，发现以下关键缺陷：
1. **主渲染循环同步网络阻塞（致命）**：TUI 主循环每秒在单线程中串行 `await` 3 个 HTTP 请求，网关离线时阻塞达 1.5s~4.5s，导致用户按键和界面完全假死。
2. **模型状态双源不同步与网关丢失模型（致命）**：`ponyllm serve` 启动时直接取 `p.models`，丢弃了 `model_configs` 中的模型，导致网关路由和 `/v1/models` 无法感知新配置的模型。
3. **默认模型切换与删除产生幽灵数据（严重）**：
   - `set_default_model` 切换时旧默认模型被直接覆盖而丢失，新模型在 `models` 中残留冗余；
   - `remove_model` 尝试删除 `default_model` 时仅删除了其配置，但主模型依然残留并被重新复活，返回虚假成功。
4. **删除末尾模型后光标悬空越界（严重）**：TUI 删除最后一项模型后未对 `model_table_state` 进行收敛校准，导致详情卡片空白且后续操作假死。
5. **小终端下模态框被裁切与按键误触（严重）**：小尺寸终端下模态框缺乏保底高度，操作提示被截断；焦点在 Provider 列表时误按 `s` 会静默触发副作用。

## Decision

1. **异步后台遥测轮询解耦（Async Telemetry Worker）**：
   - 将网络轮询移至独立后台异步协程，通过 `tokio::sync::mpsc` 单向发送遥测快照；
   - TUI 主循环仅消费 mpsc 消息，按键和渲染保持毫秒级即时响应，彻底杜绝网络波动导致的 UI 假死。
2. **模型状态原子迁移与一致性保证**：
   - `ponyllm serve` 启动时通过 `p.list_all_models()` 完整提取所有已配置模型名称；
   - `set_default_model` 实现原子迁移：旧默认模型自动回流至 `models` 列表，新默认模型从 `models` 中剔除；
   - `remove_model` 显式拦截对当前激活 `default_model` 的删除，返回友好报错指导用户先切换主模型。
3. **光标自适应收敛与空状态防崩**：
   - 删除操作后自动调用 `scroll_table` 校准 `model_table_state`，列表为空时重置为 `None`；
   - 空列表状态下按 `e` / `d` / `s` 增加友好拦截提示，避免无响应假死感。
4. **模态框小屏保底高度与交互加固**：
   - 模态框增加保底尺寸（最小高度 14 行或全屏安全自适应）；
   - 模态切换提示明确为数字键 1-4 切换，表单关键字段增加非空校验；
   - `s` 设为主模型按键增加 `tab2_focus == Tab2Focus::Models` 前置判定。
5. **TOML 字段顺序规范化与 CLI 模态白名单**：
   - `ProviderSection` 调整字段顺序（标量在前，表数组在后），杜绝 TOML 解析降级；
   - CLI `model add` 增加模态白名单校验（`text, image, video, audio`）。

## Alternatives considered

- **在删除默认模型时自动选取下一个模型作为默认主模型**：
  - *否决理由*：自动推测可能不符合用户的路由意图（尤其在生产环境有多模型不同计费与能力差异时），显式拒绝删除并要求用户指定新默认模型更安全严谨。

## Consequences

- TUI 达到高可用工业级交付标准：即便在断网或高延迟环境下，界面操作依旧丝滑无卡顿；
- 模型与 Provider 的增删改查在内存、磁盘 TOML、CLI 以及 Server 路由层之间保持 100% 数据闭环与一致性。
